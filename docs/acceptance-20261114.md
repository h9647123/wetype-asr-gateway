# v0.2.0 流式识别验收

2026-11-14。真实部署为 Ubuntu 网关、Windows VM、WeType 3.0.0.38、配套修改构建的 Windows bridge 0.3.4。CAM 使用客户端固件 v0.4.30-cam。未升级 WeType 或修改输入法版本锁定策略。

## 真实服务器与板端

| 验证 | 结果 |
| --- | --- |
| 约5.55秒公开普通话样例，实时200ms上传，连续3轮 | 每轮结束前7次非空文字更新，均得到最终完成标记；首次出字约2.19–2.23秒，最终约7.32–7.34秒 |
| 2秒时断开，再进行正常识别 | 原生槽位释放，后续识别成功 |
| 精确60秒 PCM（循环公开样例） | 结束前90次非空文字更新，最终约60.96秒，原生槽位释放 |
| 原 multipart 文件识别接口 | HTTP 200，公开样例返回完整文字 |
| CAM 经公网 WSS 的真人语音 | 录音期间多次更新，接受了变短修订，最终确认成功；用户确认持续更新、内容正确、操作正常 |
| CAM 采音/发送完整性 | 968960字节，板端采音与服务器收到的PCM SHA-256相同；I2S溢出、缓冲溢出、读取错误和削波计数均为0 |
| CAM 数据保护 | 烧录仅更新应用分区；Flash对话分区与刷写前哈希相同，原会话未作为测试消息提交给模型 |

上述每项覆盖的是所列环境与样例。60秒测试使用预录音循环，不是60秒真人准确率测试。首次出字计时包括样例自身的发声位置，不等于说完首字后的延迟。未进行 CER/WER 或多人并发准确率基准，不能承诺每个字都单独且立即出现。

第一轮板端操作曾被息屏唤醒消耗，实际未启动录音，已排除出成功样本；显式唤醒并确认采音启动后完成上述真人验收。录音中画面的验证来自用户实屏确认，串口截图仅用于最终草稿检查，不将空闲画面截图冒充录音中截图。

## 自动化与源码交付

- 公开网关32项测试通过，包含真实 localhost WebSocket、中间快照、修订、最终确认、断开、取消、超时、限额和兼容接口。
- 生产适配器17项隔离测试通过；其额外录音归档仅用于私有诊断，公开网关不写录音归档。
- Windows补丁在固定上游提交的独立工作区成功应用，95项 Python 单测及 JavaScript 回调/encoder 所有权测试通过。
- Windows源码补丁与所构建源码一致；配套 portable 与 SHA256SUMS 随发行版提供，保留上游及依赖许可证。

公开交付不包含原始用户音频、个人会话、私有地址、API key、签名 URL 或未脱敏运行日志。

## 升级注意

先备份并更新 Windows stream-capable bridge，再升级 Linux 实时网关。旧文件识别包装层不一定支持流式；这类部署用独立 `stream_upstream` 指向实际 Windows bridge，原 `upstream` 保持不变。客户端必须在录音期间上传，才能在录音结束前看到结果。总音频60秒限制包含尾音。

此验收验证了生产部署所对应的代码路径；公开参数化配置与所有操作系统/输入法版本的组合仍须各自验收。
